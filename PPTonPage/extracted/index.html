Drop-in web component

Embed a live PowerPoint deck on any page.

Point the component at a .pptx URL and it renders inline — keeping the click-by-click animations, slide transitions and hyperlinks the original file was authored with. One script tag, no plugin, no server-side conversion.

Playing itself — click or press → to take over ← back G all slides F fullscreen

Two lines to install

The bundle registers a <pptx-viewer> custom element. It is framework-agnostic and renders inside a shadow root, so nothing on your page can leak in and break the slides.

Any HTML page

<!-- once, anywhere on the page -->
<script src="https://your-host/pptonpage/pptx-viewer.js"></script>

<!-- then, as many decks as you like -->
<pptx-viewer
  src="https://your-host/decks/quarterly.pptx"
  slide="1"></pptx-viewer>

React / Vue / Svelte

// Custom elements work in every framework.
// In React 19+ props map straight to attributes.
import './pptx-viewer.js';

export default function Deck({ url }) {
  return (
    <pptx-viewer
      src={url}
      theme="light"
      onPptxSlidechange={handleChange}
    />
  );
}

What carries over from the original file

The renderer draws each slide as real DOM — SVG geometry plus positioned text — so individual shapes can be animated. The animation layer reads the deck's own p:timing and p:transition XML rather than guessing.

Entrance & exit animations

Fade, wipe, fly-in, zoom, spin, dissolve, blinds, checkerboard, wedge and more — replayed step by step, in the order the author set.

Slide transitions

Push, wipe, split, cover, cut, dissolve, comb, circle, diamond, wheel, zoom and fade — including reverse playback when you step backwards.

Hyperlinks & click actions

Text links, shape click actions and "jump to slide" buttons stay live. Every navigation fires a cancelable event first.

Navigation built in

Click-to-advance, arrow and space keys, Home/End, a thumbnail grid, a progress bar and native fullscreen — all keyboard accessible.

Charts, tables & SmartArt

Native charts render through ECharts; tables, gradients, custom geometry, preset shapes and SmartArt layouts are all drawn faithfully.

Responsive & self-contained

Scales to its container at the deck's true aspect ratio, honours prefers-reduced-motion, and styles cannot collide with your page.

Attributes, methods, events

Everything is optional except src. Attributes are reactive — change slide and the viewer navigates.

Attributes
AttributeDefaultDescription
src—URL of the .pptx. Cross-origin needs Access-Control-Allow-Origin on that host.
slide1One-based starting slide; set it later to navigate.
animationsonoff skips effects and jumps to each step's end state.
controlsdefaultnone hides all chrome for a kiosk-style embed.
themeautolight uses a lighter letterbox behind the slide.
click-advanceonoff stops a body click from advancing the deck.
loopoffPresent: wraps from the last slide back to the first.
credentialssame-origininclude sends cookies with the deck request.

Methods & properties

const v = document.querySelector('pptx-viewer');

v.next();                 // next animation step, then next slide
v.previous();
v.goToSlide(4);           // zero-based
v.goToStep(2);            // -1 = nothing revealed yet
v.toggleFullscreen();

v.slideCount;  v.slideIndex;
v.stepCount;   v.stepIndex;

  console.log(e.detail.slideCount));

Serving it from Flask

Rendering is entirely client-side, so the backend only serves two things: the bundle and the deck. The included blueprint adds the CORS headers a cross-origin embed needs, plus range requests, ETags and path-traversal protection.

app.py

from flask import Flask
from pptonpage import pptonpage

app = Flask(__name__)

app.register_blueprint(
    pptonpage(
        decks_dir="/srv/decks",
        # or ["https://intranet.example.com"]
        allowed_origins="*",
    ),
    url_prefix="/pptonpage",
)

Routes it adds

GET /pptonpage/pptx-viewer.js
GET /pptonpage/decks/<name>.pptx
GET /pptonpage/decks/            # JSON index

# Already serving decks yourself? You only
# need this header on the .pptx response:
Access-Control-Allow-Origin: *

Worth knowing

  • Effects are driven by the deck's actual animation behaviours, not a preset-ID lookup table, so an unrecognised effect degrades to a clean fade instead of vanishing.
  • Slides are rendered lazily with a small cache window, and the next slide is prefetched while the browser is idle.
  • Animation groups that PowerPoint marks "start after previous" replay automatically; groups set to "on click" wait for you.
  • A slide set to advance automatically after a set time honours that timing.
  • Embedded video and audio are rendered as static shapes — playback is not wired up in this version.
  • Effects with no CSS equivalent (3-D rotations, some morph transitions) fall back to a cross-fade.
  • The deck host must send CORS headers, otherwise the browser refuses to hand the bytes to the component.
