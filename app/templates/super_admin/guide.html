IT Super Admin Portal Documentation

A comprehensive reference guide for managing the Aditya LMS application state, database records, and authentication mappings.

1. Overview & Scope

The IT Super Admin Portal is designed strictly for system administrators, IT staff, and database debuggers. Unlike standard Business L&D Admins who handle learning material uploads, batch allocations, or scheduling details, Super Admins have direct read/write access to the database engine and the capability to restructure user roles globally.

2. Secure IT Login

Super Admin access is controlled separately from standard database user models:

  • Isolated Credentials: Handled out-of-band via environment variables (SUPER_ADMIN_USERNAME and SUPER_ADMIN_PASSWORD) located inside the server’s .env file.
  • Default Credentials: Fallback login defaults to username: superadmin and password: superpassword if env variables are empty.
  • Session Flags: Sets session['super_admin_logged_in'] = True upon successful login, separate from standard admin flags.
3. L&D Route Bypass

IT Super Admins hold bypass privileges allowing them to execute any business administrator operation:

  • Automatic Authentication: When logged into `/super-admin`, you do not need to enter standard admin credentials.
  • Access L&D Features: Simply navigate to /dashboard or any other business admin route (e.g. Courses, Scheduled Classes, Reports). The route-guard automatically lets you in.
  • Scope: Allows you to manually override class locks, grant course extensions, change quiz questions, or edit attendance rosters.
4. User Roles & Manager Mapping

Under the User & Role Management section, you can perform direct account transitions:

  • Promote to L&D Admin: Creates an active record inside the admin_users credentials database table. The default password is set to the user’s Global ID.
  • Demote to Learner: Deletes the corresponding L&D Admin record, preventing them from logging in as an administrator.
  • Configure Manager Mappings: Assign reports-to chains dynamically using the Reporting Manager dropdown on each row.
5. CSV Bulk Imports

You can bulk-import user mappings using standard comma-separated files. Click Download Template inside the upload tool to obtain a sample CSV.

CSV Column Definitions
Column Name Description Format/Options Mandatory?
global_id Unique identifier for the user profile (e.g. employee ID) Alphanumeric / Numbers Yes
name Full display name of the user Text string Yes
email Contact email address Valid email format (or blank) No
department Company branch or team assignment Text string No
manager_global_id Global ID of the reporting manager Must match an existing or newly imported user’s global ID No
is_admin Elevate the user to an L&D Admin account automatically yes, 1, true (any other value defaults to learner) No

6. SQL Query Runner Console

The **SQL query Runner** enables executing raw SQL queries directly on the SQLite database:

  • SELECT Queries: Returns a formatted data table preview of matching records.
  • Modifying Statements: Statements such as `UPDATE`, `INSERT`, `DELETE`, or structural changes like `ALTER TABLE` return the count of affected rows.
Caution: Modifying database records via raw queries bypasses SQLAlchemy ORM validations. Always backup the database before performing updates or structural alterations.
7. Database Backups & Restores

Backing up and restoring the SQLite database can be performed with one click on the DB Dashboard:

  • DB Backup: Generates and downloads a complete snapshot of the lms.db file.
  • DB Restore: Overwrites the current application database with the uploaded backup file. The system automatically releases active database connections dynamically before saving to prevent locks.
